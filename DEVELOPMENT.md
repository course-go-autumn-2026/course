# Подготовка первой лабораторной

Рабочая ветка: `lr1`. Все команды выполняются из корня репозитория AvitoCourse.

## Генерация и сборка

Нужен Go версии, указанной в `go.mod` (или новее). Генератор закреплён в
`go.mod` как tool dependency; отдельная установка не требуется.

```sh
make generate
make build
make test
```

`contracts/openapi/trip-service.openapi.yaml` — неизменённая копия контракта
курса. `oapi-codegen.yaml` выбирает только `createTrip`, `getTrip`,
`finishTrip`, `health`, `ready`. Результат: `api/api.gen.go`.
Сгенерированный файл не редактировать вручную.

Генератор создаёт модели, интерфейс ServerInterface, маршрутизацию chi и
разбор параметров. Реализация обработчиков находится в `internal/handler`, сервис — в
`internal/service`, запуск приложения — в `cmd/trip-service`.

## Окружение

Нужны Docker Desktop и `tripgoctl`, доступные через PATH.

```sh
make environment
tripgoctl environment status
tripgoctl connect
```

Для этой работы `environment.toml` включает только PostgreSQL. `tripgoctl`
создаёт локальные `.env` и `.tripgo/`; они исключены из Git. Адрес подключения
берите из `DATABASE_URL` в `.env`. Не копируйте секреты в исходники.

```sh
tripgoctl environment stop  # остановить окружение с сохранением данных
```

## Работа с базой

Модель поездки находится в `internal/model`, интерфейсы репозитория и
менеджера транзакций, а также их реализации для PostgreSQL — в
`internal/repository`. Интерфейс сервиса и его реализация находятся в
`internal/service`. HTTP-интерфейс генерируется из контракта в `api`.

Репозиторий работает с переданным `pgxpool.Pool`: `Create`, `FindByID`,
`FindAll`, `Update`, `Delete`, `CreateStatusHistory`. При создании репозитория
и менеджера транзакций нужно передать ненулевой таймаут. `FindAll` возвращает
все поездки без пагинации. `Update` изменяет только активную поездку и поэтому
защищает от повторного завершения.

Чтобы запись поездки и истории была атомарной, вызывайте оба метода внутри
одного `TxManager.Do`. Сам репозиторий не добавляет историю автоматически.
Внутри `Do` репозиторий использует транзакцию из контекста; вне `Do` работает
с пулом. Вложенный `Do` использует ту же транзакцию. Ошибка или паника
откатывают внешнюю транзакцию, паника передаётся дальше. Выбран уровень
изоляции `Read Committed`: ограничение на активного водителя обеспечивается
уникальным индексом, а завершение — условием в `UPDATE`.

Миграции goose создают таблицы `trips` и `trip_status_history`. Команда
`make migrate` применяет миграции. `make migrate-down` откатывает последнюю
миграцию и удаляет данные откатываемой таблицы.

## Запуск сервиса

Поднимите окружение, примените миграции и запустите сервис из корня:

```sh
make environment
make migrate
make run
```

`make environment` создаёт `.env` через `tripgoctl` и добавляет настройки
таймаутов HTTP из `.env.example`. `make run` читает конфигурацию из `.env`.
Проверка доступности сервиса — `GET /health`, проверка БД — `GET /ready`.

Переменные окружения:

- `HTTP_ADDR` — адрес HTTP-сервера; `LOG_LEVEL` — уровень логирования.
- `SHUTDOWN_TIMEOUT` — время на завершение активных запросов.
- `HTTP_READ_TIMEOUT`, `HTTP_READ_HEADER_TIMEOUT`, `HTTP_WRITE_TIMEOUT`,
  `HTTP_IDLE_TIMEOUT` — таймауты HTTP-сервера.
- `DATABASE_URL` — адрес PostgreSQL из окружения `tripgoctl`.
- `DATABASE_MAX_CONNS`, `DATABASE_MIN_CONNS` — размеры пула соединений.
- `DATABASE_CONNECT_TIMEOUT`, `DATABASE_QUERY_TIMEOUT` — таймауты подключения,
  запросов и транзакций.
- `DATABASE_MAX_CONN_LIFETIME` — максимальное время жизни соединения.

Обязательные переменные проверяются при запуске. Примеры значений находятся в
`.env.example`. Для проверки сборки и выполнения имеющихся тестов используется
`make test`; в первой лабораторной отдельные тесты пока не написаны.
