## 1. Цель работы

Выделить HTTP-обработчики из общего файла `main.go` в отдельный пакет `handler`.

Реализовать взаимодействие с сервисным слоем через интерфейс, обеспечив разделение HTTP-логики и бизнес-логики приложения.

## 2. Выполненная работа

В рамках своей части проекта я:

1. Создал отдельный пакет `handler`.
2. Реализовал три HTTP-обработчика для управления бронированиями.
3. Добавил структуры для обработки JSON-запросов и ответов.
4. Реализовал преобразование строковых дат в `time.Time`.
5. Создал интерфейс `BookingService` для взаимодействия с сервисным слоем.
6. Реализовал централизованную обработку ошибок.
7. Добавил тесты HTTP-обработчиков с использованием `httptest`.

## 3. Реализованные HTTP-обработчики

| HTTP-метод | URL | Назначение |
|---|---|---|
| POST | `/bookings` | Создание бронирования |
| GET | `/bookings/{id}` | Получение бронирования |
| PATCH | `/bookings/{id}/time` | Изменение времени бронирования |

Обработчики принимают HTTP-запросы, вызывают соответствующие методы Service и формируют HTTP-ответы.

## 4. Структура пакета

`booking_handler.go` — HTTP-обработчики, интерфейс `BookingService`, регистрация маршрутов.

`requests.go` — структуры JSON-запросов и ответов, преобразование даты и времени.

`errors.go` — обработка ошибок и преобразование их в HTTP-коды.

`booking_handler_test.go` — тестирование HTTP-обработчиков.

`README.md` — документация моей части проекта.

## 5. Обработка ошибок

Реализовано преобразование ошибок приложения в HTTP-статусы:

| HTTP-код | Описание |
|---|---|
| 400 | Некорректные данные запроса |
| 404 | Бронирование не найдено |
| 409 | Конфликт бронирования |
| 500 | Внутренняя ошибка сервера |

Для проверки ошибок используется `errors.Is()`.

## 6. Архитектура

Handler отвечает только за HTTP-взаимодействие.

Основные обязанности:

- Получение HTTP-запросов.
- Чтение и формирование JSON.
- Проверка формата входных данных.
- Вызов методов сервисного слоя.
- Формирование HTTP-ответов.
- Преобразование ошибок в HTTP-коды.

Бизнес-правила бронирования, хранение данных и взаимодействие с внешними сервисами вынесены в другие слои.

Для взаимодействия с Service используется интерфейс `BookingService`, содержащий методы `Create`, `Get` и `Reschedule`.

Это позволяет уменьшить зависимость HTTP-слоя от конкретной реализации бизнес-логики.

## 7. Тестирование

Для тестирования используется стандартный пакет Go `net/http/httptest`.

Он позволяет проверять HTTP-обработчики без запуска настоящего HTTP-сервера.

Команда запуска тестов:

`go test ./handler -v`

Полная проверка проекта:

`go test ./...`

Окончательная проверка тестов и интеграция с Domain и Service выполняются после объединения кода участников команды.
