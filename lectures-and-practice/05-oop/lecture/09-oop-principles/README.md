## Абстракция: что важно для задачи

Начните с `Travel`: функции нужна только способность проехать расстояние. Интерфейс `Car` выражает эту возможность методом `Drive`. Конкретный `PetrolCar` также умеет открывать лючок бензобака, но `Travel` не зависит от этой детали.

Раскомментируйте `car.OpenFuelLid()` внутри `Travel` и покажите ошибку компиляции. Затем верните комментарий. Метод есть у конкретного типа, но отсутствует в контракте параметра.

Абстракция шире интерфейсов: это выбор существенных для задачи свойств и действий. Интерфейс Go здесь служит одним из способов выразить такой выбор. Он не является механизмом безопасности: вызывающий код мог бы намеренно проверять конкретный тип, но тогда зависимость от детали появилась бы снова.

## Полиморфизм: кто выполняет общий контракт

В `[]Car` лежат значения двух конкретных типов. Один и тот же код `Travel` вызывает `Drive`, а реализация определяется конкретным значением внутри интерфейса. Общая базовая структура не требуется, соответствие интерфейсу неявное.

Отличие акцентов: в первом примере обсуждаем, какие возможности видит потребитель; во втором - как разные реализации выполняют один контракт. На практике абстракция и полиморфизм часто проявляются в одном фрагменте кода.

## Наследование: что используется в Go

Классическое наследование позволяет строить производный тип на основе базового. В Go такого наследования структур нет. Здесь показаны доступные механизмы:

- `PetrolCar` содержит именованное поле `engine`. Его собственный `Start` явно делегирует запуск двигателю.
- `EmbeddedCar` содержит встроенное поле `Engine`. Метод `Start` продвигается, поэтому можно написать `embedded.Start()`.
- Собственный `EmbeddedCar.Name` скрывает продвинутый `Name` для внешнего вызова, но внутри `Engine.Start` по-прежнему вызывается `Engine.Name`. Виртуального переопределения через встраивание нет.
- Вызов `InspectEngine(embedded)` не компилируется. Нужно передать конкретный компонент: `embedded.Engine`.

Предложите предсказать вывод `embedded.Name()` и `embedded.Start()`, затем запустите программу. Для дальнейшего разбора используйте соседние примеры `02-composition` и `03-shadowing` в папке лекции.

## Инкапсуляция: доступ и правила изменения

`PetrolCar` находится в отдельном пакете `vehicle`. Его поле `speed` неэкспортируемое, поэтому код в `main` не может обращаться к нему напрямую. Это настоящая граница пакетов, а не условная договорённость внутри одного `package main`.

Метод `SetSpeed` поддерживает инвариант `0 <= speed <= 180`. При значениях `-10` и `200` он возвращает ошибку и сохраняет прежнюю скорость `80`. Граничные значения `180` и `0` принимаются. `Speed` возвращает копию числа, не предоставляя возможности изменить поле через результат.

Раскомментируйте `car.speed = -10` в `main.go`, покажите ошибку компиляции и верните комментарий. Обсудите, почему скрытого поля было бы недостаточно, если бы публичный метод позволял записывать любое число. Код внутри самого пакета `vehicle` по-прежнему имеет доступ к `speed` и должен соблюдать правила типа.
