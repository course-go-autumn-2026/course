# Десять вариантов практики по ООП на Go

Варианты подготовлены по структуре исходного практикума «Пиццерия» из
[oop-practice](https://github.com/course-go-autumn-2026/oop-practice).
Исходное задание находится в отдельном репозитории по ссылке выше.

| № | Вариант | Составная модель во втором задании |
|---|---|---|
| 1 | [Кафе](01-cafe/README.md) | Завтрак |
| 2 | [Цветочная мастерская](02-flower-shop/README.md) | Весенний букет |
| 3 | [Кинотеатр](03-cinema/README.md) | Киновечер |
| 4 | [Прокат велосипедов](04-bike-rental/README.md) | Набор для прогулки |
| 5 | [Фотостудия](05-photo-studio/README.md) | Семейная съёмка |
| 6 | [Груминг-салон](06-pet-grooming/README.md) | Полный уход |
| 7 | [Прокат настольных игр](07-board-games/README.md) | Игровой набор |
| 8 | [Автомойка](08-car-wash/README.md) | Комплексная мойка |
| 9 | [Компьютерная мастерская](09-computer-workshop/README.md) | Обновление компьютера |
| 10 | [Копицентр](10-print-shop/README.md) | Учебный комплект |

Каждый вариант — самостоятельный проект с `go.mod`, условиями, стартовым кодом,
тестами и `cmd/demo`. Папку можно выдать студенту отдельно.

Во всех вариантах одна структура и сопоставимый объём работы:

1. **SOLID:** найти минимум три проблемы, исправить одну и проверить тестом.
   Для продвинутых — выделить зависимости, добавить опцию и проверить порядок побочных действий.
2. **Cohesion и coupling:** разделить расчёт цены и оформление чека,
   расширить состав набора и сохранить оба формата и экранирование HTML.
3. **Интерфейс из бизнес-кейса:** определить нужный контракт, подключить клиент,
   внедрить зависимость и проверить бизнес-код заглушкой.
   Для продвинутых — адаптировать второй API, округлить единицы и унифицировать ошибки.

Это задания для студентов со стартовым кодом, а не готовые решения.
Исходные тесты проходят и фиксируют базовое поведение. Намеренные проблемы
первого и второго заданий предстоит найти, объяснить и исправить студентам.
Второй клиент третьего задания возвращает дробные рубли и минуты,
чтобы проверка округления была содержательной.

## Запуск одного варианта

Нужен Go 1.22 или новее. Внешних зависимостей нет.

```sh
cd variants/01-cafe
go test ./student/...
go run ./cmd/demo
```

Если уже открыта папка `variants`, используйте `cd 01-cafe`.
Три задания внутри каждого варианта независимы.
Цены между заданиями не связаны: каждое использует свою небольшую модель.

## Проверка всех вариантов

Из каталога `lectures-and-practice/05-oop/practice`:

```sh
sh variants/check.sh
```

Скрипт запускает `go test ./...`, `go vet ./...` и пример для каждой папки.
Go не обходит вложенные модули автоматически, поэтому для общей проверки
используйте скрипт выше.

## Формат сдачи

- Код и тесты выбранного варианта.
- Таблица проблем SOLID с последствиями и предлагаемыми изменениями.
- Краткое объяснение распределения ответственностей во втором задании.
- Контракт интерфейса третьего задания: входные данные, единицы измерения и ошибки.

Проверяйте сохранение исходного поведения и обоснованность изменений.
Количество интерфейсов и типов само по себе не является критерием качества.
