## 1. Структура проекта

**Структура** отвечает на вопрос «где лежит код», **архитектура** — «как части системы взаимодействуют». Единообразная структура помогает быстрее разобраться в чужом сервисе.

| Каталог | Назначение |
| --- | --- |
| `cmd/<app>/` | Точки входа: сборка зависимостей и запуск приложения. |
| `internal/` | Внутренние пакеты: обработчики, бизнес-логика, работа с хранилищем. |
| `api/` | Контракт API: пути, параметры, схемы запросов и ответов. |
| `pkg/` | Иногда используется для переиспользуемых пакетов; необязателен. |

Это соглашения, а не обязательный стандарт Go. Особое правило есть у `internal`: импорт разрешён только коду внутри дерева родительского каталога. Точка входа — `func main()` в `package main`; имя файла `main.go` условно. Создавайте каталоги по необходимости, общие библиотеки лучше выделять в отдельные модули. [Структура Go-модуля](https://go.dev/doc/modules/layout).

## 2. Сервер, маршрут и обработчик

**HTTP API** — интерфейс взаимодействия через HTTP. **Endpoint («ручка»)** задаётся методом и путём, например `GET /api/v1/items/{id}`. **Роутер** выбирает обработчик; `http.NewServeMux()` создаёт роутер, а `http.ListenAndServe` запускает сервер.

**Handler** обрабатывает запрос. Интерфейс `http.Handler` содержит метод `ServeHTTP(http.ResponseWriter, *http.Request)`. Функцию с такими аргументами регистрируют через `HandleFunc`. `*http.Request` содержит входные данные, `http.ResponseWriter` — интерфейс для записи ответа. JSON кодирует пакет `encoding/json`. [net/http](https://pkg.go.dev/net/http).

Параметр пути читают через `r.PathValue("id")`, query-параметр `?id=42` — через `r.URL.Query().Get("id")`. Шаблоны с методом и `{id}` поддерживаются стандартным роутером начиная с Go 1.22. [Маршрутизация](https://go.dev/blog/routing-enhancements).

Минимальный пример по задаче занятия: сохраните как `main.go`, запустите `go run main.go`. Это учебный сервер без middleware и graceful shutdown.

```go
package main

import (
    "fmt"
    "log"
    "net/http"
    "strconv"
)

func main() {
    mux := http.NewServeMux()
    mux.HandleFunc("GET /api/v1/items/{id}", func(w http.ResponseWriter, r *http.Request) {
        id, err := strconv.Atoi(r.PathValue("id"))
        if err != nil || id <= 0 {
            http.Error(w, "id must be a positive integer", http.StatusBadRequest)
            return
        }
        if id != 42 {
            http.NotFound(w, r)
            return
        }
        w.Header().Set("Content-Type", "application/json")
        if _, err := fmt.Fprintln(w, `{"id":42,"title":"lamp"}`); err != nil {
            log.Printf("write response: %v", err)
        }
    })
    log.Fatal(http.ListenAndServe("127.0.0.1:8080", mux))
}
```

Проверка: `curl -i http://127.0.0.1:8080/api/v1/items/42` → **200** и JSON. Замените `42` на `abc`, `0`, `-1` → **400**; на `43` → **404**. В PowerShell при необходимости используйте `curl.exe`. В примере ошибки текстовые; для рабочего API согласуйте единый формат ошибок в контракте.

**Рекомендации:** проверяйте входные данные до бизнес-логики; после ответа об ошибке делайте `return`. Заголовки и статус задавайте до тела: первая запись тела без `WriteHeader` отправит **200**. После изменений перезапускайте сервер; при ошибке запуска проверяйте адрес и занятость порта. [ResponseWriter](https://pkg.go.dev/net/http#ResponseWriter).

## 3. Middleware

**Middleware** — обёртка вида `func(http.Handler) http.Handler`: выполняет общую работу до/после обработчика или останавливает запрос. Логирование, измерение времени, проверку доступа и восстановление после паники удобно выносить сюда. Порядок обёрток влияет на результат.

В лекции использован **chi** — роутер, совместимый с `net/http`. `r.Use(middleware.Logger)` добавляет логирование, `r.Use(middleware.Recoverer)` — обработку паник; `r.Route("/api/v1", ...)` объединяет маршруты под общим префиксом. В chi параметры пути обычно читают через `chi.URLParam(r, "id")`. Middleware подключайте до маршрутов. [Документация chi](https://github.com/go-chi/chi).

Уточнение: `net/http` уже перехватывает панику внутри `ServeHTTP`, но может оборвать соединение/HTTP-поток. Recoverer помогает сформировать управляемый ответ, когда это ещё возможно. Он не перехватывает паники в произвольно запущенных горутинах и не заменяет проверку ошибок. [Поведение Handler](https://pkg.go.dev/net/http#Handler).

## 4. Graceful shutdown

**Graceful shutdown** — корректное завершение сервера, например при перезапуске приложения. Последовательность: получить сигнал остановки → прекратить приём новых соединений → дождаться текущих запросов → освободить ресурсы.

Используйте `http.Server`, `signal.NotifyContext` и `Server.Shutdown` с отдельным контекстом и тайм-аутом. Контекст остановки создавайте от `context.Background()`: контекст сигнала к этому моменту уже отменён. Дождитесь завершения `Shutdown` в `main`; `http.ErrServerClosed` после остановки ожидаем.

Тайм-аут — предел ожидания, а не обязательная пауза. Если он истёк, `Shutdown` вернёт ошибку и сам не оборвёт активные соединения: при необходимости явно вызывают `Close`. Это механизм плановой остановки, а не восстановления после паники. [Server.Shutdown](https://pkg.go.dev/net/http#Server.Shutdown).

## 5. API-first и OpenAPI

**API-first**: сначала согласовать контракт с клиентами, затем реализовать сервис. Добавление обязательного параметра может сломать существующих клиентов; изменения контракта нужно согласовывать.

**OpenAPI** — машиночитаемое описание HTTP API в YAML/JSON: `paths` и методы, `parameters`, `requestBody`, `responses`, общие модели в `components/schemas`. `operationId` идентифицирует операцию; `$ref` ссылается на переиспользуемую схему. Для path-параметра обязательно `required: true`; положительный ID описывается как `type: integer`, `minimum: 1`. [OpenAPI 3.0.3](https://spec.openapis.org/oas/v3.0.3.html).

**Кодогенерация** создаёт типы и серверную обвязку из контракта. В занятии используется `oapi-codegen` с `types,chi-server`. Реализуйте сгенерированный интерфейс и подключите обработчики к роутеру. Сгенерированные файлы вручную не редактируйте: меняйте схему и повторяйте генерацию; фиксируйте версию генератора.

Генерация не заменяет полную валидацию: преобразованный `int` ещё не гарантирует `id > 0`. Ограничения схемы проверяйте валидирующим middleware, бизнес-правила — в своём коде. В режиме `types,chi-server` не рассчитывайте на автоматическое декодирование любого тела запроса. [oapi-codegen](https://github.com/oapi-codegen/oapi-codegen#requestresponse-validation-middleware).

**Для закрепления:** добавьте GET-операцию в схему, сгенерируйте обвязку, реализуйте и вызовите её; задание со звёздочкой — POST с телом запроса. Сверяйте `operationId`, префиксы маршрутов и пути вывода генератора.
