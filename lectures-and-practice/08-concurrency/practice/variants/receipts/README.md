# Вариант 06. Чеки и касса

Нужен Go 1.23+. Запустите `go test -run '^TestLegacy' ./...`: эти тесты уже проходят.

Заполните TODO в `practice.go`. Свои тесты можно добавить в `student_test.go`.
Остальные файлы не меняйте. Готовые legacy-функции используйте только как пример.

## 1. Горутины и Mutex

В `PrintAllReceipts(items, work)` запустите по горутине на элемент. Вызывайте `work` ровно
один раз с исходным элементом, вне блокировки. Записывайте результат в общую
`map` по индексу под одним `sync.Mutex`. Дождитесь всех горутин через
`sync.WaitGroup` и верните результаты в исходном порядке.

Не меняйте входной срез. Для пустого входа верните пустой срез или `nil` без вызовов
`work`. ID могут повторяться. `work` не равна `nil`, безопасна для конкурентного
вызова, завершается и не паникует.

## 2. Fan-out и Fan-in

Реализуйте обе функции в `practice.go`. Порядок результатов произвольный.

- `FanOut(in, workers, work)` сразу возвращает `workers` разных ненулевых каналов.
  Ровно `workers` горутин читают общую очередь. Каждую задачу обработайте один раз и
  отправьте результат в канал своего воркера. После исчерпания закрытой очереди
  каждый воркер закрывает свой выход. При `workers <= 0` верните пустой срез или
  `nil`, не читая вход и не вызывая `work`.
- `FanIn(streams...)` сразу возвращает общий выход. Читайте каждый вход в отдельной
  горутине и передавайте каждое сообщение один раз. Открытый пустой вход не должен
  задерживать остальные. Закройте выход после всех входов через `sync.WaitGroup`,
  в том числе при нуле входов.

Отправители закрывают входные каналы; получатель читает выходы до конца.
Входные каналы не равны `nil`. Для `work` действуют те же условия, что в задании 1.
Не вызывайте функцию первого задания. Отмена в этой части не нужна.

## 3. Тикер и отмена

Реализуйте `RunCashReport(ctx, interval, report) error`:

- При `interval <= 0` верните `ErrInvalidInterval`, даже если контекст уже отменён.
  Иначе для уже отменённого контекста верните `ctx.Err()` без вызова `report`.
- Создайте один `time.NewTicker`. В `select` ждите `ticker.C` или `ctx.Done()`.
  Вызывайте `report` по тикам синхронно, начиная с первого тика.
- При отмене верните `ctx.Err()`. Остановите тикер через `defer ticker.Stop()`.
  Не закрывайте его канал. После возврата отчёты должны прекратиться.

Контекст и `report` не равны `nil`. `report` выполняется быстро и не паникует.
Отмена не прерывает начатый вызов. Если тик и отмена готовы одновременно,
`select` может выбрать любое событие.

## Проверка и сдача

Не используйте `time.Sleep` для синхронизации или активное ожидание в `select`.

```sh
gofmt -w practice.go student_test.go
go test -timeout 30s ./...
go test -race -timeout 30s ./...
```

Чтобы проверить одну часть, запустите `go test -run` с одним из префиксов:
`'^TestAcceptanceBatch'`, `'^TestAcceptanceFan'`, `'^TestAcceptanceClock'`.

Сдайте проект и вывод проверок в `TEST_RESULT.txt`. Если на Windows не настроен
C-компилятор для `-race`, запустите обычные тесты; гонки проверит преподаватель.
За каждое выполненное задание — 1 балл. Зачёт — от 2 из 3 при собирающемся проекте.
